# 证据、论点与推理规范 V0.1

## 区分四个东西

- **来源 Source**：原始标准、检测报告、论文、厂家技术文件、现场记录及其版本。
- **证据条目 Evidence**：从来源中提取的可核实观察、测量、试验结果或文本要求，保留页码/定位、对象、方法、条件。
- **论点 Claim**：可真可假、有边界且可被支持或反驳的判断。
- **推论 Inference**：根据多个论点、上下文和规则产生的结论，记录推理路径及仍然未知之处。

一份来源可产生多条独立证据；同一证据可支持多个论点；同一论点可收到相反证据。不能把新闻转载 A/B/C 当作三个独立实验。来源与证据、证据与论点均为多对多，保留引用链和 source_root_id 便于归并。

## 最小证据字段（拟扩展 Schema）

evidence_id、source_id、source_root_id、原始链接/馆藏定位、来源拥有者/作者、版本与日期、访问/核验日期、具体页码或测量位置、方法与条件、观察值及单位、原样摘要（遵守版权）、适用范围、合法使用状态、可信度与审核状态。

## 论点关系

support（支持）、refute（反驳）、qualify（限制）、depends_on（依赖前提）。在关系边记录方向和适用条件。显式区分直接测量、对照结果、理论机制、经验推测、商业广告和未经确认的表述。

**不得将“有证据”作为真值证明**：需要核对适用条件、标准版本、样本和测试方法；缺乏反证不等于证实。

## 推理案例

“增加一道防水涂刷是否值得”：先获取具体涂料的技术文件和目标膜厚要求，再比较同总用量或同每遍用量两种配置的人工、工期和验收结果；若对照条件不同，则不把性能差异归因于“遍数”。

“为什么有人只做一遍”：减少工序在某种计费模式下可能改变激励，这是结构性假设；除非有现场访谈、施工记录或其他直接证据，否则不能判断某个具体人的真实动机。

## 输出答案必须展示

结论、适用条件、主要证据、相反证据或限制、未知项、推导路径、更新时间。可使用“已核实 / 有条件支持 / 存在争议 / 证据不足”之类非绝对性的状态，不要未经校准给出看似精确的置信度百分数。
