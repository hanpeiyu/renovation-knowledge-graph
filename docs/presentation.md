# 展示与交互设计 V0.1

## 共用数据、分层呈现

**客户模式**：按空间、产品、装修问题、AI 问答进入；第一页以“要做什么、为什么、在何种条件下、风险/成本差异和证据状态”为主。适合展示可视化产品拆解、场景化方案比较和引用来源。

**设计师模式**：额外展示构造、材料、工序、参数范围、适用标准、节点深化需求、计算边界和交付验收。

**研究模式**：完整知识关系、论点的支持/反驳、来源树、推理链、冲突证据及审核历史。

## 核心交互

- 产品示意图上点门锁→锁舌→材料或表面工艺，关联复用通用工艺卡；
- 先看“某种锁具适不适合潮湿卫生间”的有条件建议，再点开证据；
- 证据链可追溯到报告版本、具体页面和检测条件；展示相反证据；
- 从门本体切换到“供货安装可用的门”，显示额外工作、验收与责任边界；
- 防水参数配置比较必须明确同总用量/同单遍用量，以及目标性能指标。

## 前台架构

GitHub Markdown/YAML 为权威来源 → 派生结构化索引/搜索/关系图 → Web 前端或 AI 问答。Obsidian 适合编辑体验，但直接展示全量网状图不适合作为普通客户的默认首页。网站未在本次 V0.1 实现。
