# 工艺、工序、配置、执行与交付 V0.1

## 核心分层

1. **Process 工艺定义**：要达到何种技术目的、通常有哪些工序和技术约束。
2. **Process step 工序**：输入、动作、输出、所需工具、参与角色、前置条件、停工/验收条件。
3. **Process configuration 工艺配置**：对具体材料和场景约束下的参数选择，如遍数、总用量、重涂条件、目标膜厚。
4. **Execution record 现场执行记录**：计划/实际时间、测量值、人员、天气/基面状态、偏差、照片/文档链接；这是项目实例数据，**原则上不直接混进通用百科节点**。
5. **Deliverable 交付成果**：完成且满足规定验收要求的状态或对象，例如“安装合格的室内门”。
6. **Offering 商业交付项**：采购合同中“供货+安装”的范围、责任、计价及不包含项。

## 防水施工的抽象流程

基层检查及处理 → 按具体产品说明配制 → 第一次涂刷 → 层间状态检查/允许重涂 → 后续涂刷（按配置）→ 养护与检查/验收。

警告：不是所有防水产品都要求或允许加水；不同产品重涂条件与用量不同。此处**不给统一加水比、遍数、小时数**。须引用指定产品的最新技术文件和适用标准，并结合温湿度、基层、目标厚度等。

## 参数/约束/因果

- 参数：coat_count、amount_per_coat、total_consumption、target_dry_film_thickness、waiting_condition、temperature、humidity。
- 约束：对某一产品、基面与环境，只有满足指定条件才能进入下一工序。
- 因果候选：改变总用量可能改变材料成本；增加到场次数可能改变组织成本；未达到重涂条件可能影响成膜，具体风险取决于材料和证据。

任何因果关系都应记录证据级别。禁止把“固定等待越长越好”写成通用规则。

## 交付边界：一樘门

door 是 physical_object；install-door 是 activity；installed-door 是 deliverable；supply-and-install-door 是 offering。隐形门可以额外关联方案设计、节点深化、五金选型、界面协调、现场复核等 activities。是否单独收费取决于商业包，不可等同于是否发生实际成本。
