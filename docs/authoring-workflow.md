# AI 内容生产、审核与质量守门 V0.1

## 基本闭环

1. GitHub Issue 写清单项范围：目标节点/关系、需要的字段、未解决的工程问题、来源检索范围和验收标准。
2. AI 查原始来源，收集证据条目，标记来源独立性/时间/条件/版权限制。
3. 按模板生成 Markdown/YAML 草稿；不确定或无证据处保留空值与 unverified 状态。
4. 建关系，不凭关键词相似性偷换“包含”“影响”“导致”“支持”等含义。
5. 运行结构校验，检查 ID 唯一、目标存在、词表合法、格式与 Schema。
6. Pull Request 由人工核实证据质量、推理越界、遗漏场景、资料版本、版权和报价口径。
7. 审核通过再合并；更新派生索引和网站，并在变更日志记录影响。

## 例行审阅三问

证据是否可靠且真正独立？主张是否越过证据条件？结构和成本边界是否完整且可复用？

## 完成标准

基础元数据正确 + 引用完整 + 证据授权清晰 + 工程判断有条件 + 同一概念无重复 + 通过自动检查 + 完成人工审查。对“draft/未核实”的示例，仅要求清楚标识，不可声称正式知识已上线。

## 自动化边界

脚本能发现无效 YAML、重复 ID、坏引用、非法关系与部分状态冲突；但无法自动确认产品说明是否最新、检测是否伪造或一个因果论断是否真的成立。人工审阅是必要环节。
